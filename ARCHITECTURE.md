## 🔄 RAG 工作流程

```
┌──────────────────────────────────────────────────────────────────┐
│                     1. 文档上传和索引阶段                         │
└──────────────────────────────────────────────────────────────────┘

   用户上传文档 (PDF/Word/TXT)
         │
         ▼
   ┌──────────────────┐
   │ document_loader  │  ← 解析文档，提取文本
   │ 文档加载         │
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │ document_chunker │  ← 将长文档切分为小块
   │ 文档分块         │     (500字符，重叠100)
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │ embedding_client │  ← 调用 API 将文本转为向量
   │ 向量嵌入         │     (1536维 或 1024维)
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │  vector_store    │  ← 存储到 ChromaDB
   │  向量数据库       │     (持久化到 data/chroma_db/)
   └──────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                      2. 问答查询阶段                              │
└──────────────────────────────────────────────────────────────────┘

   用户提问: "RAG系统有哪些组件？"
         │
         ▼
   ┌──────────────────┐
   │ embedding_client │  ← 将问题向量化
   │ 问题嵌入         │
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │   retriever      │  ← 在向量库中搜索相似文档
   │   检索器         │     (Top-K=3, 余弦相似度)
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │  rerank (可选)   │  ← 重排序，结合关键词匹配
   │  结果优化        │
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │    generator     │  ← 将检索结果 + 问题发送给 LLM
   │    生成器        │     生成答案（流式输出）
   └────────┬─────────┘
            │
            ▼
   返回答案 + 引用来源
```

## 🔧 配置管理架构

```
┌─────────────────────────────────────────────────────────────┐
│                      配置加载流程                            │
└─────────────────────────────────────────────────────────────┘

1. 启动应用
     │
     ▼
2. app/config.py 加载
     │
     ├─→ 读取 .env 文件
     │       OPENAI_API_KEY=sk-...
     │       DEFAULT_EMBEDDING_PROVIDER=ollama
     │       CHUNK_SIZE=500
     │       ...
     │
     ├─→ pydantic-settings 解析
     │       • 类型验证
     │       • 默认值填充
     │       • 环境变量覆盖
     │
     ▼
3. 生成全局 settings 对象
     │
     └─→ 所有模块通过 from app.config import settings 访问

┌─────────────────────────────────────────────────────────────┐
│                      配置使用示例                            │
└─────────────────────────────────────────────────────────────┘

# app/core/embedding_client.py
from app.config import settings

api_key = settings.openai_api_key
base_url = settings.openai_base_url

# app/core/vector_store.py
from app.config import settings

persist_dir = settings.chroma_persist_dir
collection_name = settings.collection_name

# web_app.py
from app.config import settings

server_host = settings.server_host
server_port = settings.server_port
```

## 📊 日志系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                      日志流转                                │
└─────────────────────────────────────────────────────────────┘

应用启动
    │
    ├─→ app/utils/logger.py 初始化
    │       │
    │       ├─→ 配置控制台 handler (彩色输出)
    │       │       format: <green>时间</green> | <level>级别</level> | ...
    │       │
    │       └─→ 配置文件 handler
    │               path: logs/rag_{time:YYYY-MM-DD}.log
    │               rotation: 500 MB
    │               retention: 10 days
    │
    ▼
各模块调用日志
    │
    ├─→ from app.utils.logger import get_logger
    │   logger = get_logger(__name__)
    │
    ├─→ logger.info("操作成功", user_id=123)
    │       │
    │       ├─→ 控制台输出:
    │       │   2026-08-04 22:00:00 | INFO | module:function:42 - 操作成功
    │       │
    │       └─→ 文件输出:
    │           logs/rag_2026-08-04.log
    │           2026-08-04 22:00:00 | INFO | module:function:42 - 操作成功
    │
    └─→ logger.error("失败", error="...")
            (同时输出到控制台和文件)
```

## 🎯 性能监控架构

```
┌─────────────────────────────────────────────────────────────┐
│                   监控数据收集                               │
└─────────────────────────────────────────────────────────────┘

# 装饰器方式
@track_time
def embed_texts_batch(texts):
    # 函数执行
    │
    ├─→ 开始计时: start_time
    ├─→ 执行函数逻辑
    ├─→ 结束计时: end_time
    └─→ 记录日志: elapsed = end_time - start_time
            logger.info("函数执行完成", elapsed_time="2.5s")

# 上下文管理器方式
with Timer("向量化"):
    # 代码块执行
    embedding_client.embed_texts_batch(texts)
    │
    ├─→ __enter__: 开始计时
    ├─→ 执行代码块
    ├─→ __exit__: 结束计时
    └─→ 记录日志: logger.info("计时完成", elapsed_time="2.5s")
```

## 🎊 总结

这个架构具备：

✅ **清晰的分层** - UI → 应用 → 数据 → 外部服务  
✅ **松耦合设计** - 配置、日志、监控独立模块  
✅ **可扩展性** - 易于添加新功能和服务  
✅ **可维护性** - 统一的配置和日志管理  
✅ **可测试性** - 依赖注入，便于 Mock  

适合用于：
- 🔬 **研究**: 便于修改和实验
- 🚀 **生产**: 可直接扩展到生产环境
- 📦 **部署**: 为容器化做好准备
