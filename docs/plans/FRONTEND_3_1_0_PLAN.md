# DocuMind 3.1.0 前端优化实施计划

编写日期：2026-09-20。基线：当前源码版本 3.0.0。目标：形成可复审的 3.1.0 候选源码；本计划不表示新版本已经发布。

## 1. 目标与范围

改善长回答与多轮对话的流畅度、中文可读性、键盘操作和引用核对体验，同时降低前端维护成本。保留现有 React/FastAPI 架构、主要布局与深绿视觉方向。

本轮必须完成：

- 流式消息更新隔离与适度批量刷新，保留停止、报错和完成时的全部已接收正文。
- 自动滚动尊重用户阅读位置，提供明确的回到底部操作。
- 按职责拆分现有组件及必要的会话、流式和文档操作逻辑。
- 补齐常用设计变量，收拢重复色值，提高小字号文本可读性。
- 统一弹窗基础行为和确认交互，补齐焦点管理；统一提示样式与语义。
- 正文 `[文档N]` 引用定位到所属回答的具体来源。
- Markdown 代码语法高亮，以及克制的空状态引导。
- 回归测试、性能对照、视觉检查、版本同步和复审材料。

本轮排除：Tailwind/shadcn 全面迁移、zustand/外部 store 引入、暗色主题、导入导出、全站骨架屏、上传/删除乐观更新、消息虚拟化、后端业务重构、检索算法调整和真实数据重新评测。发现范围外问题先记录，不顺带修复。

## 3. 架构与兼容约束

### 3.1 模块职责

建议结构如下，可依源码调整文件名，不为满足目录示意创建空文件或重复抽象：

```text
frontend/src/
  App.tsx                         # 页面组装与少量协调
  components/                     # DocumentItem、DocumentDetailsDialog、ConversationHistory 等
                                  # MessageList、MessageItem、Composer、SourceItem、Notice、Dialog
  hooks/                          # useChatStream、useConversations、必要的 useDocuments/滚动逻辑
  features/chat/                  # 流式缓冲、消息状态转换、Markdown 与引用处理
  conversations.ts                # 保留既有持久化职责
  api.ts                          # 保留网络/SSE 解析职责
  types.ts
  styles.css                      # 可按需要拆样式，但不能产生两个 token 真源
```

- TanStack Query 继续管理文档、详情和服务状态等服务端数据；组件不重复缓存同一份数据。
- 会话状态优先使用 React 状态或 reducer；流式计时器/缓冲可放 ref 或独立小模块。
- 会话状态持有者负责不可变更新，流式模块负责请求及缓冲生命周期，Markdown 模块负责呈现及引用交互。
- 为消息提供稳定身份与尽可能稳定的 props/callback。只给整个 MessageList 套 memo，不能证明历史消息已隔离。
- 优先按现有组件边界拆分，再收拢状态；组件不能靠接收整份 App 状态恢复原有耦合。

### 3.2 必须保留的行为

- SSE 的 sources/status/token/done/error 事件形态、公开错误语义和停止请求能力。
- 上传、索引、查看详情、重新索引、删除文档、服务不可用提示及恢复刷新。
- 新建、切换、清空、删除会话，以及浏览器刷新后恢复历史。
- `rag-workbench-conversations-v1` 的数据兼容性与既有保存上限。
- 引用编号属于每条回答的来源集合，不能以文件名或当前最新 sources 代替身份。
- `/api/v1/retrieve` 保持 Schema `1.0`、`dense-v1` 和现有业务行为；本轮仅允许必要的应用版本标识与示例同步。
- Markdown 保留安全默认行为，不开启不可信原始 HTML，不使用字符串拼接注入 HTML。

### 3.3 依赖选择

- 保留现有手写 CSS；设计变量采用语义色、常用字号/间距/圆角/阴影的有限集合，不把每个数值都变成变量。
- 代码高亮默认评估 `rehype-highlight`，确认与当前 react-markdown/Vite 兼容，限制常用语言集合；未知语言按纯文本安全显示。不得同时引入两套高亮引擎。
- 引用使用 Markdown AST 转换和明确的交互节点；react-markdown v10 不能直接照搬旧版 `components.text` 方案。
- 弹窗优先评估 `@radix-ui/react-dialog` 的最小接入；确有充分理由可复用轻量实现，但完整焦点与背景隔离验收要求不变。
- FE-01 记录推荐依赖的实际版本、用途、替代方案和体积影响估计，阶段确认后再安装。新依赖写入直接依赖并同步 lockfile，不依赖偶然存在的传递依赖。实际体积增量在 FE-06 复核。

每阶段收尾须提供证据、测试结果、未关闭问题和下一阶段内容，给出 PASS / PASS WITH NOTES / FAIL，并等待人工阶段确认。获得实现授权不等于获得提交、推送、tag 或发布授权。后续若有明确更新的阶段执行授权，按该授权处理并记录。

### FE-01：建立可复现基线

1. 记录起始 Git HEAD、分支、工作树变更、Node/npm/Python/浏览器版本；不覆盖已有未提交内容。
2. 阅读 App、样式、API、类型、会话持久化、测试、Mock API、CI 及当前版本文档。核实本计划假设，不把旧文档版本当作源码版本。
3. 运行现有前端单测、类型检查、构建和六条现有 E2E。记录实测数量及原有失败，禁止写死“应有六条所以六条通过”。
4. 用隔离 Mock 构造可重复的高频流式样例：50 条已完成消息；追加约 10,000 个字符的回答，含中文段落、列表、表格、代码及引用；约 10ms 一次分块。固定文本、分块序列、发送间隔和环境。
5. 记录历史消息渲染/Markdown 解析次数、流式 React commit 次数、主线程长任务或帧耗时、字符可见延迟、构建体积；浏览器与 React 计数须说明开发/生产/StrictMode 条件。
6. 留下桌面、窄屏和弹窗的基线截图；明确现有滚动及键盘缺陷。性能工具不足时记录未测指标和原因，不能以肉眼估计替代数字。
7. 形成明确模块接口、拟新增依赖和验证方式。首阶段不修改生产行为，允许添加仅测试使用的夹具/测量设施。

交付：基线报告、复现方式、原有问题列表、依赖决定、后续阶段详细任务。FE-01 未通过不得把后续优化收益写成已证实。

### FE-02：必要拆分与状态整理

1. 移出现有组件，抽出 MessageItem/MessageList 和 Composer，保留当前 UI 与语义。
2. 收拢会话与消息的状态转换；在有利于可测试性时使用 reducer。网络读取和消息归并保持可独立验证。
3. 抽出流式请求的创建、中止及清理职责；文档查询/操作继续交给 Query，不另建全局数据副本。
4. 明确每次生成绑定的 conversationId、answerId 和请求身份，后续到达的旧事件不能污染新会话。
5. 保留 stream 期间新建/切换/删除的既有产品约束；若既有行为存在串写风险，给出证据并在本阶段修复身份绑定，不凭空增加交互限制。
6. 运行前端检查与既有 E2E；只为关键状态转换增加行为测试，不为“文件已拆开”写测试。

验收：App 以组装为主；模块职责清晰；原有会话、文档和 SSE 行为不回退；不以行数或文件数量宣称完成。

### FE-03：流式更新与滚动

1. 让已完成且内容未变化的消息跳过重复 Markdown 解析。确认 callback、插件数组等引用不会使 memo 失效。
2. 当前回答按约 50ms 初始刷新间隔合并 token；首段尽快呈现。以基线决定是否调整，不硬编码“每 token 更新全局状态”。
3. 明确 flush/discard 规则：正常完成、显式 error、网络异常、EOF、手动停止应保留已收到但尚未显示的文本；卸载/销毁时清理资源且不能写入其他会话。未收到 token 的 done.message 回退仍正确。
4. 防止旧计时器、旧响应和 finally 清理误操作下一次请求；清理应可重复执行，兼容 React 开发模式生命周期。
5. 正文保存仍在合适的稳定时机执行；停止/完成后刷新页面应恢复完整已接收内容，不把写盘频率提升为每个 token。
6. 仅在用户接近底部或主动回到底部时跟随新内容；向上阅读时停止跟随并显示“回到最新”。发送问题、切换会话和手动回底行为需一致且可预测。
7. 避免逐 token 启动 smooth 动画；考虑 reduced-motion，且来源面板滚动不能带动整个聊天区。

必测边界：token 后立即 done、token 后立即 error、停止恰在刷新前、停止后马上重发、无 token 完成、连续来源/状态事件、异常断流、刷新恢复、旧请求清理与新请求并存、卸载。

性能验收：固定高频样例中，未变历史消息的 Markdown 解析不随 token 数增长；刷新次数与合并周期相关；50ms 初始方案下 token 内容批次通常不超过约 20 次/秒，首批和终止 flush 单独统计。前台 Mock 下新增可见等待目标不超过 100ms，报告中列实测与噪声。前后至少各 3 轮报告中位数及范围；不能仅以 memo 存在或构建通过替代性能证据，也不能把合成基准外推为所有设备收益。

### FE-04：设计变量与基础交互

1. 在现有语义颜色基础上补足侧栏、焦点、成功/警告/错误等变量，建立有限的 spacing/radius/font-size/shadow 等级。
2. 常用正文维持约 14px；关键辅助文字优先 12px，密集次要元数据可用 11px；清理承载有效信息的 9–10px 字号。
3. 同步调整行高、容器和间距；中文、长文件名、长标题、标签不能因提字号重叠或丢失操作入口。文本对比度按普通文字至少 4.5:1 验证，焦点清晰可见。
4. 统一 Notice 外观和语义；操作相关错误保留在上下文，不强制全部改成自动消失的 Toast；进度不能逐 token 向屏幕阅读器播报。
5. 弹窗打开后焦点进入，Tab/Shift+Tab 不逃出，关闭后恢复到触发点；触发点已删除时有合理回退目标。背景不可操作，Escape/遮罩行为一致。
6. 保留删除请求进行中的必要限制；取消为破坏性确认的默认安全焦点。避免文档详情与删除确认两个焦点循环互相争抢。
7. 检查来源抽屉若在窄屏表现为模态遮罩，须同样具备背景隔离和焦点恢复；若为非模态区域则不谎报 aria-modal。

验收视口至少：1440×900、860×900、390×844 和 320px 宽；另测 200% 缩放。聊天区、来源面板、弹窗和按钮可用；宽表格/代码可在自身区域横向滚动，不能撑破整页。视觉截图与键盘测试都需完成。

### FE-05：引用、代码与空状态

1. 只把准确形式 `[文档N]` 且能映射到该回答有效来源的引用转换为可交互 chip，保留可读标签和键盘操作语义。
2. 核查后端生成上下文、SSE sources 和 rank 的实际对应关系；不得仅凭数组位置猜测编号。选择身份使用 messageId + rank，必要时附 chunkId。
3. 点击时先选中所属回答的 sources，再打开来源区域，待目标挂载后滚动定位并高亮；跨回答同编号、同名文件不同 chunk 不得串指向。
4. 不转换 inline code、fenced code 和已有链接内的文本，避免嵌套交互；不存在/越界/格式错误的编号保留普通文本，不跳到另一来源。
5. 覆盖同段多引用、重复引用、列表/表格引用、分块未闭合引用、sources 晚到、历史会话恢复、手机来源区域展开、点击两个回答的同编号引用。
6. 使用与 react-markdown v10 兼容的 AST/组件方案，保持 URL 安全限制；自定义节点不得使模型文本绕过安全策略伪造任意跳转。
7. 代码高亮至少验证 Python、JavaScript/TypeScript、JSON、Bash、无语言及未知语言代码块；流式未闭合围栏不崩溃，inline code 保持简洁，长代码不撑宽页面。
8. 高亮加入后重复关键性能样例，避免优化后又被高亮全量解析抵消；必要时流式阶段使用简化显示、完成后高亮，但须说明并保证切换平稳。
9. 空知识库引导上传；有文档无对话可提供 2–3 个通用提问建议，点击只填入输入框，不自动发起模型请求，不暗示知道具体文档内容。

验收：新增行为测试与浏览器用例通过；正文引用指向准确且可由键盘操作；安全 Markdown 和未知语言退化行为保持；高亮后的性能回归有数据。

### FE-06：整体验证与版本收尾

1. 对照范围与兼容矩阵逐项验收，修复本轮回归，不扩大功能范围。
2. 汇总前后测量、视觉截图、测试日志、依赖/构建体积增量；检查是否残留调试计数器、生产 console 噪声或一次性测量代码。

4. 逐处判断版本含义；禁止全仓替换 `3.0.0`，不能修改第三方依赖的同名版本、历史报告、3.0 迁移说明或旧发布记录。版本历史新增 3.1.0 条目，并明确是源码候选而非已发布 Release。
5. Schema `1.0` 与 `dense-v1` 不变。版本修改后再次运行版本一致性和必要的 Python/契约检查。
6. 完成下列最终检查与交付报告，状态为“待复审候选”。尚有必验项阻断时使用“未完成验收”，不得标记整体通过。

## 5. 验证命令与证据边界

前端目录 `frontend/`：

```powershell

npx playwright install chromium
npm test
npm run typecheck
npm run build

```

仓库根，FE-06 版本同步后至少执行：


最终候选还需复核现有 CI 门禁，执行项目要求的完整离线检查；若已在同一最终代码状态运行通过，不重复执行：

```powershell
python -m pytest -q
python -m black --check app evaluation tests
```
